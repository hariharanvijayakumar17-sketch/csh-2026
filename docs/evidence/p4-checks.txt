## 2. Enforcement model (S1) — where what runs
- EDGE middleware (src/middleware.ts): resolves EVERY /api/v1 request against
  the route-policy registry (unregistered → 404 envelope; wrong method → 405
  with allowed list), S9 CSRF on ALL mutating requests (same-origin Origin +
  JSON-only), x-request-id stamping.
- NODE route handlers: makeRouteHandler() — the single factory. Permission
  routes: session from cookie → DB resolve → can(user, permission, ctx).
  Public routes: optional session. Standard envelope everywhere.
- The registry test (S1, P3) still walks the registry: 5/5 after adding the
  clarifications GET + openapi entries (1:1 rule preserved).

## 4. Notes / caveats
- Session cookie: HttpOnly, SameSite=Strict, Path=/, maxAge 30 d, Secure in
  production. Value = raw 256-bit token; DB stores sha256 (P3 S9).
- CSRF = Origin/Host + JSON-only (P3 design, proven here over real HTTP).
  Non-browser clients must send Origin on mutations (k6/Playwright do).
- Errors never leak internals: unexpected error → 500 generic envelope
  (observed: the openapi runtime error returned the generic envelope while
  the detail went to server logs only).
- Problems public surface = published AND non-deleted ONLY (integration test
  "item: lists ONLY published, non-deleted"; drafts/deleted invisible).
- /api/v1/teams (and other P5+ routes) are registry-resolved (405/404 shape
  correct) but 404 until P5 ships their handlers — expected, not a gap.
- OpenAPI: single source of truth = the Zod route schemas via src/lib/zod.ts
  (all routes import z from there; direct "zod" imports in routes are
  forbidden — see DECISIONS D20; bundler duplicate-instance bug found live).
- E2E (Playwright full journey) is P9 per plan; the smoke above is the P4
  HTTP-level proof.
